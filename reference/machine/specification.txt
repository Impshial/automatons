# Implement The Machine and Operatorton

Implement this complete feature in the existing Automatons mod for Minecraft 1.20.1. The Machine is a Lumina-powered, rideable multiblock vehicle that can clear land, bore tunnels, follow simple programs, and be operated by a new automaton job called Operatorton.

Read the repository instructions and inspect the current implementation before editing. Reuse the project's loader, mappings, registries, networking, automaton jobs, pedestal network, Lumina systems, protection checks, inventories, rendering, and GUI conventions. Do not change the Minecraft version or introduce a second framework. Implement the feature, build it, and run relevant checks. Do not stop after writing a plan or producing placeholders. You can organize the work into internal stages, but the requested result is the complete feature.

This prompt is self-contained. Where it conflicts with older Machine notes, use this version. Its final attachment rule is particularly important: attachments cannot be toggled; they are physically installed or removed through the GUI while The Machine is stopped.

1. SCOPE AND TERMINOLOGY

- The vehicle's displayed name is "The Machine". Do not call it Dozer or Bulldozer in player-facing text.
- The driver job is "Operatorton".
- Use Lumina terminology consistently. Reuse the existing registered Lumina/Core items rather than making duplicates under slightly different names.
- The attachments are "Blade Attachment" and "Bore Attachment". Earlier references to a Drill Attachment mean the Bore Attachment.
- The reusable instruction item is named "Program". Do not use books, written books, or loose paper as the programming interface.
- The Machine has Manual, Chunk, and Program modes.
- A player or an Operatorton can occupy its single Operator Station. It also supports unattended Chunk and Program work without a seated pilot.
- Implement all necessary items, assembly blocks, recipes, models, textures, sounds, interfaces, persistence, and multiplayer synchronization.

The following defaults settle details that were not specified numerically. Keep them easy to adjust, and mention any changed default in your completion notes:

- Communication range: a horizontal circular radius of 48 blocks from the linked pedestal, equivalent to three chunks. Check the whole vehicle footprint, including an attachment, rather than only its center. This is an explicit implementation default for the previously ambiguous word "radius".
- Manual movement uses cardinal headings, with smooth animations between them. A/D request 90-degree turns. This keeps driving consistent with the grid, clearance rules, and program language.
- Chunk mode is a surface-clearing job for the Blade. It does not excavate the entire vertical chunk or create a quarry. Bore work uses Manual or Program mode.
- Program item recipe: the inexpensive reusable recipe in section 13. This recipe is a new default, not an existing mod recipe.
- Startup, travel, turning, breaking, fuel rates, and tank capacity should use existing balancing conventions where possible. Keep new numbers together in configuration or clearly named constants, rather than scattering magic numbers through the code.

4. ENGINE, TERRAIN, AND MOVEMENT

The Machine consumes Lumina. Reuse the existing Lumina accounting and the shared Tank/Luminall infrastructure where applicable. Do not invent another magic resource or silently assume that one fluid unit equals one Lumina. Use the existing conversion, or define one documented configurable conversion if the project does not have one.

Provide a working survival refueling interaction through the GUI using the existing mod's supported fuel or fluid containers. Preserve normal container return behavior. Do not leave survival fueling dependent on commands or creative mode.

Engine states are Off, Starting, Running, and Stopping. Starting has a short sound and animation; travel is disabled until startup completes. Stopping halts travel, turning, and block processing immediately, then plays the shutdown presentation. Starting the engine alone must not resume an old program or move The Machine. Explicit Start Work or Resume commands may orchestrate startup and then continue their requested job.

If fuel is exhausted, stop and retain the current task and exact remaining movement. Fuel use and recovery are server-authoritative. A stopped engine consumes no fuel. Do not create an idle fuel loop that defeats the player's ability to park the vehicle.

Travel rules:
- Move along cardinal directions and maintain a stable grid-aligned logical position. Animations can interpolate smoothly.
- Rotate around the central vertical axis of the compacted 3x3 chassis. The attachment is offset in front of that pivot.
- Check the swept chassis, attachment, and rider clearance through a turn. Do not check only the destination bounding box or allow the attachment to swing through walls.
- A turn by itself does not mine or clear blocks.
- Use collision that allows a correctly aligned Bore and seated operator to travel through a 3x3 tunnel. Do not use an oversized collision envelope that makes the tunnel it creates impassable.
- Climb one block only when there is a supported step across the full three-block travel width and adequate body/rider clearance. A single narrow raised block is not a climbable step.
- Do not hop, bridge gaps, climb two blocks, or fall off unsupported edges. As a practical default, permit supported one-block descents with adequate clearance.
- Check terrain before movement. A Blade can remove eligible soft obstructions in its cutting area, but it does not make unsupported terrain into a valid step.
- Reverse movement must be supported for manual driving and returning through narrow tunnels. The attachment remains physically at the front; reversing does not turn it into a rear attachment or clear behind the vehicle.
- Stop on an obstruction, fuel shortage, unsafe terrain, or range boundary and show a specific short reason.

Link The Machine to the existing pedestal network using the project's ownership/assignment conventions. Provide a clear GUI method to select an eligible pedestal if association cannot be inferred. Use the same 48-block default limit for Manual, Chunk, and Program operation. Validate each movement and turn against the boundary. Do not allow a remote move simply because the driver is a player.

Use existing chunk-loading and protection behavior. Do not force-load unlimited terrain or bypass protected chunks and block interaction permissions. If required terrain is unavailable, pause with a clear status instead of treating missing chunks as empty space.

5. ATTACHMENTS: FINAL RULES

There is one dedicated Attachment slot in The Machine's GUI.

- Install or remove the Blade/Bore only while The Machine is deliberately parked or its job is paused, with no translation, turning, or block operation in progress.
- A brief zero-velocity instant between route steps is not permission to swap equipment during an active job.
- Validate the replacement attachment's occupied space before accepting it.
- The operation transfers the actual item to/from player inventory without voiding or duplicating it. Handle a full player inventory correctly.
- Attachment changes happen through the GUI. The wand forms the multiblock but does not swap attachments.
- No attachment toggle button, keybind, enabled flag, or HUD control exists.
- There is no hidden transport mode that disables an installed attachment. Forward movement into eligible blocks performs its work automatically.
- An installed attachment does not break blocks merely because the engine is idling. Work requires an actual advance into the relevant cutting area.
- With no attachment, The Machine is a small Lumina-powered vehicle with cargo storage. It cannot break obstacles, clear land, bore, or harvest Lumina.

Blade:
- Clears a three-block-wide line in front of the vehicle.
- Can break ordinary breakable blocks that do not require a pickaxe. Shovel blocks are explicitly allowed: dirt, grass blocks, sand, gravel, and similar materials.
- Also clears eligible logs/trees, leaves, grass, flowers, crops, pumpkins, melons, and similar vegetation or materials.
- Pickaxe-required blocks stop the Blade. Do not mistakenly restrict the Blade to plants or exclude blocks because a shovel is the preferred tool.
- Determine compatibility from the game's tool requirements and the mod's existing harvesting rules, with appropriate support for other mods. Do not implement a tiny hard-coded whitelist of only the examples above.
- Unbreakable blocks remain unbreakable. Respect the existing protected-area and block-entity handling rules.
- Reuse tree recognition/felling where appropriate so the land-clearing behavior handles real trees coherently. Do not indiscriminately flood-fill connected wooden structures as trees.
- Collect normal item drops into cargo. Collect Lumina from eligible cleared blocks using the mod's current yield rules, and credit that Lumina to The Machine's fuel supply exactly once.
- Do not invent new yields, multiply rewards across a tree, or credit the same yield to both The Machine and its rider.

Bore:
- Cuts a three-block-wide by three-block-high square immediately ahead, leaving supporting ground beneath the tunnel intact.
- The nine visible drills correspond to that 3x3 work area.
- Breaks blocks requiring a pickaxe, subject to the intended tool tier and unbreakable-block restrictions. Use diamond-equivalent capability as the default, matching its three diamond-pickaxe recipe.
- Collects normal mined item drops, but never collects Lumina or calls the Blade's harvesting behavior.
- Soft terrain/vegetation outside its supported block category is an obstruction, not something it clears using Blade logic.
- Plan multi-block cutting safely. Stop before advancing into remaining obstructions or overflowing cargo. Do not leave The Machine embedded in an incompletely cut face.

When cargo is full, prevent further breaking that would overflow it. Retain the ability to reverse or drive through already clear space to unload. Do not add an attachment-disable control to solve full storage.

- An occupied seat is occupied. Do not silently delete, duplicate, or eject Operatorton to accept a player. Expose the controlled Release Operator action described below.
- Only one pilot can control movement at a time.

Display a driving HUD only while the local player is seated. Keep the crosshair and world view usable. Show:

- Lumina fuel bar.
- Cargo capacity and a full warning.
- Installed attachment: Blade, Bore, or None. This is informational, not toggleable.

Controls:

HUD prompts are key hints; players must not need to release mouse-look and click HUD buttons to drive. Suppress movement input while editing a GUI. Opening a screen alone does not automatically pause unrelated unattended Machines.

Dismounting parks this Machine and leaves the saved automatic job paused. It must not resume a program or let Operatorton take over until explicitly requested. Find a safe dismount position rather than placing the player inside the drills, terrain, or a wall.

8. PROGRAM LANGUAGE

Keep the language deliberately tiny. Accept uppercase and lowercase. Spaces and newlines separate instructions but are optional between unambiguous tokens. Newlines do not add delays.

Commands:
- N, S, E, W alone: turn to face that absolute cardinal direction, without moving.
- N<number>, S<number>, E<number>, W<number>: face that direction, then move exactly that many blocks.
- A distance must be an explicit positive integer. N does not mean N1. Reject zero, negative, fractional, missing/overflowed distance forms with clear validation where applicable.
- Each period means wait one second. ... waits three seconds; ..... waits five seconds.
- DROPOFF: return to this job's saved start location and unload into eligible connected/nearby chests there.

Use the game's simulation timing for pauses. Persist remaining pause time through a normal save/load. Validate the entire text before execution so an unknown command in a later line does not become a surprise halfway through work. Put reasonable bounds on text size and numeric distances; reject impossible numeric inputs instead of overflowing or freezing the server.

Examples:

- E1 means face east and move one block.
- N20 E E20 is valid. The standalone E is redundant because E20 also faces east, but it must remain valid.

9. JOB STATE, DROPOFF, AND CARGO

The four Cargo Compartments provide exactly 108 slots, equal to two double chests. Use one scrollable cargo view, not a huge off-screen inventory.
